# Qwen3-4B DSA — data plan

Training data for Phase 1 / 2a / 2b of the GQA→DSA adaptation of **Qwen3-4B-Thinking-2507**.
See [plan.md](plan.md) for the phases and [eval_plan.md](eval_plan.md) for the gates.

**Decisions (2026-07-27):**
- **Prompts only; responses always regenerated by the target model** (§1). Never train on another
  model's responses or reasoning traces.
- **Prompt selection targets difficulty and domain, not prompt length** (§2). Length is bucketed
  *after* generation, not filtered before it.
- **Long documents carry all prefill-long supervision** (§4, S1) — no instruction-shaped
  long-context task synthesis.
- **Short-half prompt banks:** Dolci-Think-SFT + Magpie-Llama-3.3-Pro (§3).

**Amendment (2026-07-30):** the S2/S3 prompt bank is now **`allenai/Dolci-Think-RL-32B`** (102,026
RLVR-filtered prompts — difficulty-selected by construction, which is exactly §2's criterion), with
Dolci-Think-SFT demoted to a short-half top-up. Build plan, verified schema, and the
`<think>`-preservation contract: [`../qwen3_4b_msa/phase2_data_gen.md`](../qwen3_4b_msa/phase2_data_gen.md).
Its prompts are p50 ~119 / max ~3.3K tokens, so it changes **nothing** about §11 — the prefill-long
gap stands.

**Constraints (user, 2026-07-27):**
- **No agentic/SWE harness available** → no on-policy agentic trajectory generation.
- **No "Route B"** (chunk-derived question synthesis over long documents).

These two constraints remove every source of *instruction-shaped* prefill-long data. The
consequence is real and is recorded in **§11 — read that section before accepting this plan.**

## 1. The governing rule: prompts only, regenerate on-policy

Surveyed every disclosed EAGLE3 draft-head recipe for Qwen3-235B-A22B (the closest available
analogue: an auxiliary module trained to imitate a frozen target). The recipe is unanimous.

| Draft head | Framework | Disclosed data |
|---|---|---|
| nvidia/Qwen3-235B-A22B-**Thinking-2507**-Eagle3 | TensorRT Model Optimizer | **6.34M samples**; prompts from Nemotron-Post-Training-Dataset-v2; *"only prompts were used to synthesize data; the original responses from GPT were not used"* |
| nvidia/Qwen3-235B-A22B-Eagle3 | ModelOpt v0.35.0 | **503.3K samples**; prompts from ultrachat_200k + Magpie-Llama-3.1-Pro-300K-Filtered, responses re-synthesized |
| lmsys/Qwen3-235B-A22B-EAGLE3 | SpecForge | UltraChat + ShareGPT (no counts disclosed) |
| Tengyunw/qwen3_8b_eagle3 | — | ultrachat_200k **prompts only**; 600K samples / 1B tokens |
| AngelSlim/Qwen3-{1.7B…32B}_eagle3 | — | nothing disclosed |

**Findings:**

1. **Public datasets are used purely as a prompt distribution.** Original responses are discarded
   and the target model generates its own. This is the same principle as the MiniCPM3 Phase-2
   self-generation pipeline (`scripts/dsa/gen_trajectories.py` → `trajectories_to_sft_parquet.py`),
   now externally validated at 235B scale. The rationale transfers exactly: a draft head and a
   lightning indexer are both auxiliary modules trained to imitate a **frozen target**, so
   off-policy responses teach them to predict a distribution the target does not have.
2. **Thinking targets need ~10× more data.** 503K–600K samples for non-thinking Qwen3 heads vs.
   **6.34M** for Thinking-2507. In tokens the multiplier is larger, since thinking samples are much
   longer. Budget Phase 2 *up* relative to the MiniCPM3 run.
3. **No draft-head card discloses a training sequence length** — because it does not matter for
   their objective (EAGLE3 needs local next-token agreement over a 3–7 token horizon). So there is
   **no long-context precedent to copy** from this literature. Length is our problem alone.

**Corollary — do not train on another model's reasoning traces.** Cloning a foreign CoT idiom is
the behavior-cloning drift that cost **−3.0 on HumanEval+** in the MiniCPM3 run
(`docs/dsa_eval_report.md` §3), and a different *family's* reasoning style would be worse.

## 2. Selection criterion: difficulty, not prompt length

Prompt length and training-sequence length come apart completely for a thinking model — a
300-token prompt with a 25K trace is a 25K training sequence.

| Regime | Length comes from | Correct selection criterion |
|---|---|---|
| **decode-long** (short prompt + long trace) | the generated trace | **prompt difficulty + domain**; prompt length is irrelevant |
| **prefill-long** (long context + short answer) | the prompt/context itself | **context length** — a hard requirement |

Prompt-length filtering is a valid rejection criterion **only** for the prefill-long regime. It has
no place in decode-long sourcing.

**Pipeline consequence — do not pre-classify prompts as short or long:**

1. Select prompts on **difficulty + domain**.
2. **Generate** with the target model.
3. **Bucket by realized sequence length** post-hoc via `scripts/dsa/analyze_lengths.py`.

The length distribution is an outcome you measure, not a property you filter on. Only S1 (§4) needs
length-targeted sourcing, because there the length is in the input.

**Difficulty proxies, cheapest first:**
- **Domain** — proof, competition math, competitive programming, multi-step derivation elicit long
  traces; creative-writing and short-form chat never will.
- **Published difficulty labels** — Magpie ships `very easy`…`very hard` per row.
- **Realized trace length from another model** — e.g. GLM-5.1-Reasoning's Math subset reports
  **mean 28,133 / median 24,498 output tokens** vs. 4.4–5.5K for its other subsets. That per-prompt
  length is a free verbosity/difficulty prior on which prompts will make Qwen3 think long, which
  replaces most of a pilot-generation sweep. **Use the metadata; discard the traces.**

Prompt-length filtering stays only as hygiene (`select_prompts.py --min-prompt-chars /
--max-prompt-chars`) for dropping junk and truncated prompts.

## 4. The three data streams

### S1 — Long real documents (prefill-long, Phase 1 + Phase 2)

The only prefill-long stream under the current constraints, and it needs **no prompts, no
generation, and no question synthesis** — just documents.

- Source: the existing InfLLM-style long-document pipeline (`examples/dsa/prepare_real_data.py`),
  one doc per row, packed to 32K, **retokenized with the Qwen3 tokenizer** (never reuse another
  model's `token_ids`).
- **Phase 1** consumes this directly: dense warm-up is pure token-level KL over documents.
- **Phase 2a/2b** reuse the *same corpus* under the sparse forward, with an LM objective. This is
  the key simplification: sparse-attention adaptation over plain long documents requires no
  instruction formatting and no response generation. Zero new data work.
- **Do not substitute synthetic haystacks.** `docs/dsa_indexer_metrics.md` records that synthetic
  random-token data drives `topk_recall` flat at the ~k/T chance floor — no attention structure to
  learn. RULER-style synthetics are an eval tool only.

**S1-opt (available, not currently planned):** an agentic trajectory transcript is *itself just a
long document*. The Nebius sets could be consumed as raw long-context text under the same LM/KL
objective — **no harness and no question synthesis required** — which would add code-flavored,
heterogeneous (code + prose + logs + diffs) long context. Recorded here as the cheapest way to
close part of the §11 gap if desired.

### S2 — Short instruct/reasoning prompts, regenerated (Phase 2 short half)

- Prompts: **Dolci-Think-SFT (60%) + Magpie-Llama-3.3-Pro (40%)**, optionally supplemented by
  Nemotron-v2 math/code/STEM and Magicoder.
- Responses: generated by **Qwen3-4B-Thinking-2507** (§1).

### S3 — Decode-long via difficulty-mined prompts (Phase 2 long half)

- Prompts: Magpie `very hard` × {math, coding, reasoning} · Dolci Think Python / Think Persona IF ·
  GLM-Math + PHD-Science prompts pre-filtered by GLM trace length · Nemotron math/code.
- Responses: generated by the target, `max_new_tokens ≈ 32768`.
- **Yield:** if p50 trace is ~4K, only the tail clears 16K → expect to generate **3–5× the rows
  kept**. Measure with `analyze_lengths.py` on a 2K-prompt pilot per slice before committing.

## 5. Mixture and bucketing

Buckets are **realized-sequence-length outcomes** (§2), not pre-selected pools.

| Bucket | Share | Stream |
|---|--:|---|
| short sequences (<4K) | 40% | S2 (whatever falls out short) |
| **decode-long** (8–32K) | 30% | S3 |
| **prefill-long** (16–32K) | 30% | S1 |

Rationale: 60% of sequences land in the 8–32K band where the selection ratio is 6–12% — the
regime the deployed model operates in. Keep code at **≥20%** of the long share: code was both the
most sparsity-sensitive *and* the most BC-fragile domain in the MiniCPM3 run.

Phase 1 uses S1 exclusively.

---

## 6. Filtering: drop pathological, do not filter for correctness

- **Drop truncated traces** — no `</think>`, or hit the token cap. These actively teach the model
  not to terminate. **Log the rate.**
- **Drop looping/degenerate traces** (n-gram repetition detector).
- **Do not reject on answer correctness.** This is behavior cloning: the goal is to reproduce the
  frozen target's distribution, not improve it. Rejection sampling on correctness shifts the data
  off-policy and defeats the purpose. Log accuracy as a diagnostic only.

---

## 7. Loss masking, and why S1 is efficient

Mask the prompt; train on `<think>…</think>` **plus** the answer. The trace is the capability being
preserved and it is most of the tokens.

**The indexer KL is computed over all valid query positions regardless of the LM loss mask.** So S1
delivers dense indexer supervision across the full 32K at essentially zero generation cost, and for
Phase 2a (base frozen, KL-only) it is close to ideal.

**Gotcha:** `trajectories_to_sft_parquet.py` was written for MiniCPM3, which has no thinking mode.
Verify it preserves `<think>…</think>` in the assistant message and that Qwen3's chat template
round-trips it — Qwen3's template strips prior-turn reasoning in multi-turn, which is correct at
inference but would silently delete the training signal.

## 8. Contamination guard

Extend `select_prompts.py --exclude-sha` to also exclude prompt hashes from the benchmarks being
gated on: **RULER · NoLiMa · HELMET · LongBench v2 · AIME · GPQA · LiveCodeBench**. Nemotron's and
GLM's math/code slices overlap competition-math and competitive-programming distributions.

## 11. Known gap: no instruction-shaped prefill-long data

**This is the main open risk in this plan.** With no agentic harness and no Route B, every
prefill-long sequence comes from **S1 (plain long documents under an LM/KL objective)**. There is no
training data of the form "long context + instruction + answer".

**What that means:**

- The indexer's prefill-long supervision is **document-shaped only**. Phase 1 covers this well
  (dense token-level KL over 32K real documents is exactly the right supervision), so the gap is
  narrower than it first appears — it is a **Phase-2** gap, not a Phase-1 one.
- But [eval_plan.md](eval_plan.md) gates on **RULER, NoLiMa, HELMET** — which are *entirely*
  instruction-shaped prefill-long tasks. We would be training on one regime and gating on another.
- The specific risk: attention over a self-generated trace has strong local/recency structure, while
  RULER-style retrieval requires attending to distant, semantically unrelated content. Trace-trained
  selection may not transfer, and the failure would appear exactly as a Δ that **grows with L** —
  the signature the eval plan is built to detect.

**How to proceed honestly:**

1. **Treat the prefill-long benchmark results as an out-of-distribution generalization test.** This
   is a legitimate scientific question ("does document-trained + trace-trained indexer selection
   transfer to instruction-shaped long context?"), provided it is reported as one rather than as a
   like-for-like result.
2. **The Phase-1 recall probe is the early-warning system.** `topk_recall` bucketed by query
   position, key distance, and needle depth over held-out long *documents* is measurable before any
   Phase-2 spend, and recency collapse there predicts RULER failure. Gate on it (Phase-1 gate 3).
3. **Cheapest available mitigations, if the gate fails**, in ascending cost:
   - **S1-opt** (§4): consume the Nebius agentic transcripts as raw long documents. No harness, no
     question synthesis, adds heterogeneous code-flavored long context.
   - Any *existing* long-context instruction dataset (no synthesis on our side) — **surveyed and
     measured 2026-08-10: [`../qwen3_4b_msa/phase2_long_context_data.md`](../qwen3_4b_msa/phase2_long_context_data.md).**
     Headline: ~34.5K rows / ~1.4B prefill tokens ≥16K available under permissive licenses, 68% of it
     `LongCite-45k`. LongAlpaca tops out at 27K tokens (0% ≥32K); the best pure-length source
     (`nvidia/ChatQA2`, 100% ≥32K) is CC-BY-NC. None of them is code-flavoured.
   - **`LoongRL` KeyChain data (arXiv 2510.19363) is the one source that is *retrieval*-shaped** —
     7,500 rows at 100% ≥16K, real prose whose answer requires exact multi-hop long-range lookups. It
     addresses the train/eval mismatch described above rather than widening it, so the "no synthetic
     haystacks" rule in §4 **does not** apply to it (that rule targets random-token documents with no
     attention structure; KeyChain's injected UUID chains are the task). Capped at ~20K tokens.
   - Reconsider Route B.

Record whichever path is taken in the run log so the scorecard's provenance is unambiguous.
